# Nanoserver-01 store A/B, ephemeral root, and miniserver profiles

## Goal
Rename the existing Nanoserver NixOS host to `nanoserver-01`, version only its NixOS system closure/store on the mirrored USB Btrfs pool, recreate `/` ephemerally at boot, move persistent/high-write state and unencrypted swap to the NVMe devices, expose the existing impermanence helpers through nix-lib, and add profiles for all three miniserver hosts.

## User decisions and constraints
- Host identity changes from `nanoserver` to `nanoserver-01`.
- All three `miniserver-01`, `miniserver-02`, and `miniserver-03` are in scope; use Nanoserver-01 as the configuration-pattern baseline, but maintain unique per-host storage UUIDs and hardware facts.
- Use distinct filesystem UUIDs and partition UUIDs/PARTUUIDs per host; mount and discover root members by UUID/PARTUUID, never by hostname-derived filesystem labels. Omit filesystem labels unless a generic role label is operationally useful. Btrfs send/receive relies on subvolume UUID/parent UUID metadata, not disk labels.
- Keep `flake.nix` a thin interface. Slot each NixOS behavior module in `hosts/features/default/`, `hosts/features/opt-in/`, or `hosts/features/opt-out/` according to its enablement scope; nix-lib provides feature discovery/resolution and shared helpers. Per-host UUIDs, paths, Facter data, hostname, and secrets references remain local.
- Use per-slot UKIs: the UKI on USB-A mounts USB-A's root member by PARTUUID, and the UKI on USB-B mounts USB-B's root member by PARTUUID. Both UKIs select the same software-versioned Btrfs store/root payload; do not make independent OS copies.
- Use the NixOS image-based-appliance operating model for the server OS: no runtime Nix or `nixos-rebuild switch`, immutable system payloads updated with `systemd-sysupdate`, and an ephemeral root with only explicitly approved state persisted. Validate the profile's effects on secrets, users, UKIs, and persistence in QEMU.
- Unencrypted NVMe swap is approved. Recommend two 8 GiB swap partitions per host, one per NVMe; zram may take higher priority. Do not enable hibernation/resume unless separately requested.
- Allocate approved high-write/persistent OS paths to the NVMe Btrfs RAID1. Keep `/tmp` volatile. User will provision `nix-secrets` and `nix-keys`; never inspect or modify their values.
- No commits or pushes. Preserve the existing dirty nix-config worktree and clean nix-lib worktree state.
- User authorized preparing Disko layouts for the current two USB and two NVMe devices on each of the three miniserver hosts. This authorizes configuration work only, not physical Disko/nixos-anywhere execution. No physical formatting/repartitioning until QEMU gates pass and stable by-path targets are rechecked immediately before any destructive command.
- The separate 4 TB Ventoy disk remains excluded from every Disko target.

## Architecture
- Follow the NixOS `image-based-appliance.nix` profile as the server OS baseline. Its appliance model disables runtime Nix and `system.switch`, makes users immutable, and expects image-level updates such as `systemd-sysupdate`; evaluate the module's exact effects with the host's secrets, user, initrd, and service configuration.
- Treat software A/B as versioned NixOS closure/store subvolumes, not independent whole-root partitions. Each version includes both slot toplevel closures under `/nix/store` and two small slot-specific UKIs. The closure-registration manifest accompanies the update bundle and is recorded under `/persist` for recovery; runtime Nix is disabled, so no Nix database is required to boot. Each ESP receives only the UKI variant whose root/store source is on that USB, while both variants select the same software version.
- systemd's `64-btrfs.rules` marks a member `SYSTEMD_READY=0` while its multi-device filesystem is incomplete. A later PARTUUID-matched Udev rule overrides readiness for these root members so the initrd can wait for and mount one local member in degraded mode.
- Boot into a tmpfs `/` and mount the selected read-only versioned store subvolume directly at `/nix/store` in the systemd initrd before executing `/nix/store/<toplevel>/init`. The sysupdate tar payload contains store paths at its archive root so it extracts into a subvolume mountable at `/nix/store`; keep a separate top-level Btrfs mount for sysupdate staging. Keep the version in the UKI command line so the initrd mounts the matching store subvolume. Explicitly recreate `/etc` from the NixOS configuration and persist only approved mutable state.
- Treat the article's `systemd-repart` auto-growth as a separate image-deployment feature, not as a reason to repartition the known physical USB/NVMe targets at boot. The fixed multi-device topology remains described by Disko, and all destructive work stays gated.
- Keep durable machine identity, the stable SSH host key, and service state on the NVMe Btrfs RAID1 `/persist`. Never copy host private keys or secret values into the versioned store closure. The root itself and disposable runtime directories are recreated on boot. Make all required `/etc`, `/var`, `/run`, and `/nix/var` semantics explicit and test them; do not assume those paths are all symlinks into the Nix store.
- Use Btrfs RAID1 and explicit impermanence mounts; do not add mergerfs. OverlayFS is only a candidate if it simplifies the ephemeral `/` layer; a tmpfs root plus a separately versioned `/nix/store` needs no mergerfs pool.
- Reserve two 8 GiB NVMe swap partitions as an initial proposal, use zram at higher priority if enabled, and leave hibernation disabled. Keep the Btrfs data area RAID1 after subtracting swap space.

## Reuse boundary
- Put the Nanoserver/miniserver appliance behaviors under `hosts/features/opt-in/appliance/` (or an equivalent feature subtree): slot-aware root/initrd readiness, dual-ESP UKI/blessing, systemd-sysupdate transfers, and the shared payload builder. Each host opts in through its feature configuration; use `default/` only for behavior meant for every host and `opt-out/` only for a broadly enabled feature that exceptional hosts disable.
- nix-lib owns the feature discovery/resolution and genuinely shared helpers such as `impermanence.mkPersistDirs`; it is not the home for these host feature modules. Keep per-host UUID/PARTUUIDs, device paths, Facter reports, hostname/network identity, persistence choices, and secret references in nix-config host profiles.
- Keep Disko tests and version-specific production update bundle publishing in nix-config. QEMU-only Nanoserver profiles and sysupdate tests were removed; a Disko generator stays in nix-config's feature tree unless it becomes a separately reusable library API; any shared layout must take devices, unique IDs, sizes, and wipe authorization as explicit inputs.
- Nanoserver's production A/B configurations and update bundle are under `hosts/nanoserver-01/{configurations,update-bundles}.nix`; the root flake imports these as wiring.

## Current evidence and blockers

Historical QEMU results below record coverage before the QEMU profiles and tests were removed; they are not currently runnable. Current automated coverage is limited to the slot-UKI evaluation check.
- nix-lib's `features.nix` already resolves default, opt-in, and opt-out features. The existing `impermanence` host feature is default-enabled and can be disabled per host with `features.opt-out = [ "impermanence" ];`.
- nix-lib's feature loader exposes `nix-lib.impermanence` helpers to NixOS modules; the helper API evaluation check passes.
- The Nanoserver Disko layout reserves two 8 GiB unencrypted NVMe swap partitions and the remainder for Btrfs `/persist` RAID1. The appliance swap feature activates both via PARTUUID at priority 10; this was previously covered by the removed slot QEMU tests. Physical install work is tracked in `docs/RESCUE-OPERATIONS.md`. Journald is volatile and `/tmp` is tmpfs.
- The `appliance` opt-in feature owns shared root/UKI/sysupdate/image/persistence/swap modules under `hosts/features/opt-in/appliance/`; the potentially destructive layout is isolated in `hosts/features/opt-in/appliance-disko/`. That layout feature sets `disko.enableConfig = false` because runtime filesystems and swap are explicitly managed by the appliance features, including mounting the NVMe data filesystem's `@persist` subvolume explicitly. Nanoserver's hostname, device paths, UUID/PARTUUID values, and Tailscale persistence remain host-local. The production Nanoserver A/B profiles opt in through nix-lib's loader.
- The NixOS `image-based-appliance` profile is imported by the appliance feature. Evaluation verifies runtime Nix and switching are disabled, users are immutable, and systemd-initrd/networkd are enabled.
- QEMU slot A and B tests boot systemd-boot directly from the selected modeled ESP using a UEFI entry keyed by its GPT PARTUUID, then reboot degraded with the peer USB removed. They verify the UKI's root PARTUUID, a tmpfs `/`, a read-only versioned store subvolume mounted at `/nix/store`, both slot toplevel closures, sysupdate and blessing, both NVMe swap devices, an ephemeral-root marker, `/var` and `/persist` markers, stable machine-id and SSH host key, and the registration sidecar under `/persist`.
- QEMU media are file-backed virtio block devices, not USB-controller devices; physical USB transport/firmware compatibility is still unproven. The initrd restores `SYSTEMD_READY=1` for configured root PARTUUIDs after systemd's Btrfs readiness rule marks an incomplete mirror unready.
- Historical QEMU update coverage used the former host-specific `nanoserver-update 2` command and exercised v1→v2 boot/fallback. Current source uses the shared `appliance-update <new-version>` interface and signed GitHub Release assets; `systemd-sysupdate.timer` polls daily and stages the store tarball, registration metadata, and both slot UKIs without rebooting. The one-shot boot selection and reboot remain operator-controlled. The QEMU tests were removed, so this update/fallback coverage is no longer runnable. See `docs/APPLIANCE-UPDATES.md` for signing, publishing, and activation.
- The QEMU gate now confirms `nix-daemon.service` is inactive, writes a test marker under `/nix/var/nix`, and verifies it is absent after v2 and degraded reboots. This validates volatile `/nix/var` behavior for the selected image profile.
- A QEMU fixture sends a small read-only Btrfs subvolume from the mirrored USB root pool to NVMe `@persist`, removes the source, receives a restored snapshot back onto the root pool, verifies contents and read-only properties, and cleans up. This validates the send/receive primitives, not full-size store backup capacity or a production retention policy.
- Slot evaluation asserts that SOPS uses systemd activation, uses the persisted SSH host key path, runs after `local-fs.target`, and persists that host key. Actual secret decryption/recovery has not been tested.
- Reconciled repository-wide Statix W04/W20 warnings in the ISO network/Tailscale modules and `wifi/NaCo.nix` by grouping repeated module attributes and using `inherit`. The Nix flake `statixCheck` now passes; generated untracked `.devenv` files were left untouched.
- The pinned NixOS swap submodule errors on device-only `swapDevices` definitions because its label option is eagerly accessed. The appliance swap feature supplies a placeholder `label` value while `lib.mkForce` keeps the actual device path PARTUUID-based; no label is created or used on disk.
- Still to validate: actual production SOPS decryption/recovery on an ephemeral root, full-size store backup capacity and retention/restore policy, full boot-count retry exhaustion without QEMU harness intervention, and all three miniserver profiles. `/nix/var` volatility and small-subvolume Btrfs send/receive primitives now pass QEMU. Both NVMe swap devices are activated at priority 10 in the slot QEMU tests. The image appliance disables runtime Nix, so its registration manifest is preserved for recovery but no runtime Nix DB is required to boot.
- Read-only inventory of miniserver-01/02/03 reports HP EliteDesk 800 G4 DM 35W systems with Intel i5-8600T CPUs, about 64 GiB RAM, two approximately 500 GB NVMe devices, and two approximately 64 GB USB devices on each; no swap is active in the rescue OS. The same non-serial by-path topology is present across all three: NVMe at PCI 01:00.0 and 02:00.0, USB at ports 9 and 10. Rescue `lsblk`/`free`/`ip` binaries returned I/O errors; `/proc` and selected `/sys` reads worked. No filesystems were formatted and no raw hardware serials were collected. Per-device filesystem UUIDs, mount layouts, and sanitized full Facter reports remain to be gathered.

## Non-goals
- Do not embed the host private key in the Nix store, root closure archive, UKI, or ordinary flake output.
- Do not edit encrypted `nix-secrets` or `nix-keys`; the user provisions them.
- Do not execute Disko/nixos-anywhere on physical miniserver disks until QEMU gates pass and the listed devices are re-identified immediately before execution.
- Do not enable LUKS, Secure Boot, hibernation, or mergerfs.
- Do not remove the current USB A/B rollback guarantee or configure unattended updates before the full QEMU gate.
- Do not rewrite legal/copyright ownership claims without evidence; raise unclear provenance for review.

## Scope and blast radius
- `nix-lib/lib/{default,builders,features,impermanence}.nix` and nix-lib tests: provide feature discovery/resolution and shared helper APIs to NixOS/Home Manager modules.
- `hosts/features/{default,opt-in,opt-out}/`: host feature modules, including appliance behaviors shared by Nanoserver and the miniserver profiles.
- `nix-config/flake.nix`, `hosts/nanoserver-01/`, `hosts/features/`, all three miniserver host directories, `tests/`, `checks.nix`, and docs.
- User-managed encrypted secret/key repositories are out of scope.
- Disko definitions may declare the approved USB/NVMe targets for miniserver hosts, but must not be executed on hardware until QEMU gates pass and live by-path identities are revalidated.
