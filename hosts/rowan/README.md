# Per-agent NixOS profiles

This directory defines the NixOS profiles for Rowan, Jules, Mira, and Avery. Each agent has its own locked Unix account (rowan, jules, mira, or avery) and guest hostname (agent-rowan, agent-jules, agent-mira, or agent-avery). Homes are /home/<agent>; the old /home/agents contents were moved, not discarded. The LXC IDs and config directories remain the short agent names.

Each LXC uses one 5 GiB ext4 image at /var/lib/lxc/rona/<agent>/agent.img. The host loop-mounts that image at /var/lib/lxc/rona/<agent>/rootfs, which is the LXC rootfs directory, not another disk. The image contains the complete NixOS root, normal /nix/store, devenv, and state. No Btrfs subvolumes, A/B slots, or separate /persist. The user-provided nixcloud-container project is only a reference: it requires NixOS, uses unconfined AppArmor, exposes the full host store, and has no guest-side daemon socket. A safer adaptation is now live on all four: the host store, DB, and daemon socket are read-only mounts, while each guest has separate writable host-side profiles and GC roots. Guest Nix clients use the host daemon as untrusted users; their local stores remain intact under the mounts for rollback. No host Nix settings or LXC confinement were changed. All guests can read the host Nix store, so secrets must never be placed there.

These are ordinary NixOS systems using the upstream LXC module; there is no guest bootloader or bare-metal Disko layout. The base image has no agent data, credentials, SSH host keys, or Tailscale state.

All four LXCs are running unprivileged with autostart disabled and UID/GID mapping 0 -> 100000, length 65536. Passwordless sudo is granted only to that guest's named account. OpenSSH remains disabled. Direct Tailscale networking was selected: each LXC now has only the /dev/net/tun bind mount and cgroup permission for character device 10:200; a TUN create/delete probe passed in each guest. CAP_NET_ADMIN was already present inside the existing user namespace, so no capability or host-wide policy change was made. Tailscale 1.90.9 is active in all four. Each agent enrolled with its own preapproved tagged key; keys were streamed from host /run tmpfs, then deleted. Each guest retains only its own Tailscale state. All four report BackendState=Running, an assigned Tailscale IP, and the default tailscale0 interface in their isolated network namespace. Tailscale SSH is enabled under the user-confirmed tailnet ACL; OpenSSH remains disabled. The shared profile suppresses only the unavailable debugfs mount and stages a guest-owned logrotate config for its check and hourly service; both fixes are active on all four.

Initial sandboxed Nix builds and a disposable devenv shell passed in each guest. A fresh Rowan devenv repeat initially failed because its previously trimmed tarball-cache repository was left incomplete. After removing only that broken cache metadata, small devenv shell and sandbox-canary tests passed in all four guests through the host daemon. Rootfs free space is Rowan 2.8 GiB, Jules 1.3 GiB, Mira 1.3 GiB, Avery 1.4 GiB. All original local stores remain intact; host GC and store cleanup are deferred. Current system profiles are host-visible roots; guest-home auto-roots that target /home/<agent> are not resolvable from the host namespace, so arbitrary guest-home roots are not yet proven safe for host GC.

The regular NixOS flake profile/install flow is used; a dedicated GitHub Actions disk-image pipeline is not required. Mara's WSL deployment uses ext4 in a VHD/VHDX and needs separate Windows-side validation.
